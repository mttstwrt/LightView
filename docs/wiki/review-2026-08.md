# Codebase review — August 2026

A pass over the whole tree looking for complexity to remove, logic to simplify,
resources being wasted, and comments/docs to improve. Recorded here so the
conclusions — including the ones not acted on — are not rediscovered.

## Overall assessment

This is an unusually well-commented codebase. Most non-obvious decisions
already carry a comment saying *why*, often with the measurement or the failure
mode that motivated them, and the shared-primitive pattern in
`src-solidjs/lib/` and the `ThumbTier::ALL`-derived table lists show a habit of
fixing duplication at the root rather than patching each site.

The defects found were consequently not sloppiness. They were **silent drift**:
two things that had to agree, agreed once, and stopped agreeing later with no
signal.

---

## Fixed

### 1. `SCHEMA_VERSION` had drifted below the migration list — *latent data-loss bug*

`cache/db.rs` declared `const SCHEMA_VERSION: u32 = 14` while `MIGRATIONS`
already contained a v15 entry. The constant's only consumer was
`detect_legacy_version`, which returned it to mean "fully up to date" — but the
ladder's last real check was `gif_atlas` (v10).

Because `run_migrations` skips every migration at or below the version it is
given, an unversioned database reaching that branch would be stamped 14 without
the justified-tier tables ever being created, and every `jm`/`jh` query against
it would then fail. Only reachable for caches predating the versioning scheme,
so probably never hit in the field — but the failure is total and silent, and
the drift was guaranteed to recur.

**Fix.** `SCHEMA_VERSION` is now derived from `MIGRATIONS` by a `const fn`, so
the two cannot separate. The ladder returns `MAX_DETECTABLE_VERSION` (10) —
what it actually verifies — and under-reporting is safe because migrations are
idempotent. `run_migrations` gained a post-condition warning for the reverse
case (a cache written by a newer build). Four tests now hold the invariants.

### 2. Non-ASCII tag queries silently lost fuzzy matching — *correctness bug*

`autocomplete::engine::fuzzy_score` counted matched **characters** while
comparing the total against `needle.len()`, a **byte** count. Any needle with a
multi-byte character has more bytes than characters, so the subsequence branch
could never succeed for it.

Invisible because the three higher-ranked branches — exact, prefix, substring —
never touched the comparison, so non-ASCII tags still autocompleted whenever
the user typed a literal prefix. Only fuzzy matching was dead, and only for
them. Verified live: `cèbû` now matches `crème brûlée`, an ASCII control still
matches, and a genuine non-match still returns nothing.

### 3. A `loop` that never looped in the SSE stream — *clippy hard error*

`http_server/routes.rs`'s `fs-changed` unfold wrapped its match in a `loop`
whose every arm returned. Harmless at runtime, but it implied a retry path that
does not exist (the tagging stream below it genuinely loops, which is what made
the shape look deliberate), and it was failing `cargo clippy` at deny level —
so the gate `AGENTS.md` advertises could not pass.

### 4. Smaller items

- **Ten near-identical schema probes** in `detect_legacy_version` collapsed
  into `has_table`/`has_column` over a version-ordered array (~80 lines → ~25).
- **A `String` allocation per candidate, per poll** in the idle worker: the
  failed-path set was keyed `(String, ThumbTier)`, so probing it required
  cloning the path. Re-keyed tier-first as `HashMap<ThumbTier, HashSet<String>>`
  so the probe borrows.
- **Four copies of the Standard tier's `(format, filter)` pair** — a real drift
  hazard, since the format string is compared against the stored column to
  decide hit-versus-regenerate — behind one `standard_tier_params()`.
- **Two over-complex tuple returns** (clippy `type_complexity`) replaced with
  `StandardTierSummary` and `TierInfo`, so `commands/media.rs` reads fields by
  name instead of `Some((_, _, fmt, has_micro))`.
- **The regeneration listener**, duplicated verbatim across both grids, is now
  `lib/thumbRegeneration.ts`.

All verified: 140 unit tests pass, and the full stack was driven end to end
against `lightview-headless` — pairing, boot state, thumbnails at three tiers,
`?fit=` resize, the SSE watcher, the auth boundary, and the real SPA in
Chromium.

## Open, in rough priority order

### A. The tree is not rustfmt-formatted — *blocks an advertised gate*

`cargo fmt --check` fails on ~70 files; formatting would be a ~4,200-line diff.
Until that one-off lands, the gate in `AGENTS.md` is aspirational, and
`cargo clippy --fix` is a trap: its let-chain rewrites leave bodies at the old
indentation and only look right after a `cargo fmt` you cannot scope. Worth
doing as its own commit when no branches are in flight. See
[`build-and-verify.md`](build-and-verify.md).

### B. ~250–300 duplicated lines between the two grids

Structurally identical fetch loops, eviction, pruning, and URL versioning, with
small policy differences that make a naive merge unsafe.
[`grid-loading.md`](grid-loading.md) inventories the differences and proposes a
four-step extraction ordered smallest-risk-first. Not attempted here: it needs
browser verification per step, and it is a larger change than a review should
land unasked.

### C. ~60 clippy style warnings

Dominated by `collapsible_if` (~22), then `new_without_default` (3),
`too_many_arguments` (6), and a handful of `map_or`/`redundant_closure`/
`io::Error::other`. Individually trivial. Best cleared in the same pass as (A),
since most of the fixes want a reformat behind them.

### D. `too_many_arguments` on the thumbnail write paths is a real smell

`write_standard_row` and `write_tier_row` take 9 arguments each, in an order
only their doc comments disambiguate — `(path, media_type, mtime, width,
height, thumbnail, format[, resize_filter])`, all positional, two of them
adjacent `u32`s. Transposing `width` and `height` at a call site would compile
and store a wrong aspect ratio. A small `ThumbRow` struct would remove the
class. Low urgency, non-zero risk today.

### E. Three stale `TODO`s

- `filter/evaluator.rs:187` — colour-label filtering falls back to a non-SQL
  path for want of a `color_label` column on `media_meta`.
- `commands/autocomplete.rs:39` — `get_recent_tags` has no persistence; recent
  tags do not survive a restart.
- `commands/settings.rs:589` — `reindex_gallery` does not kick off background
  thumbnail regeneration.

Each is a small feature rather than a defect. Worth either doing or deleting —
a `TODO` that survives long enough stops being read.

### F. `detect_legacy_version` is very likely dead code

It only runs for databases with no `schema_version` stamp, and versioning has
been in place since v1 of the schema. The ladder is now cheap and correct, so
there is no cost to keeping it, but if it can be established that no such
database exists in the wild, deleting it and treating an unstamped database as
fresh would remove the whole class of over-reporting bug that item (1) was.

### G. Absolute paths as primary keys

Every path-keyed row stores an absolute path, which is why `rebase_root` and
`infer_old_root` exist. Storing gallery-relative paths would delete that entire
mechanism, but it is a migration touching every table and every query, and the
current machinery works and is tested. Recorded as the structural observation
it is, not as a recommendation.

## Things deliberately left alone

- **The `?fit=` bypass, the decode gate, the staged upgrade, and the
  speculation gating** in the grids. These are tuned against WebKitGTK's
  main-thread decoder, several with measurements in the comments, and no
  harness available here can measure that platform. The source is honest about
  which wins are demonstrated and which are reasoned; that honesty is worth
  more than a tidier-looking refactor.
- **`http_server/api.rs`'s long dispatch match.** It looks like boilerplate,
  but it *is* the security boundary — one arm per permitted command, with the
  arg shape spelled out locally. Any abstraction that made adding a command
  easier would make widening the allowlist easier too. Verbosity is the point.
- **The per-tier `select_blob_sql`/`exists_sql` string tables.** Repetitive by
  design, so the serve path avoids a `format!` per request and `prepare_cached`
  keys on a stable string.
